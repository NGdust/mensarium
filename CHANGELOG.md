# Changelog

Версии по схеме `MAJOR.MINOR.PATCH`. Источник версии — `src/__init__.py`, релиз помечается git-тегом `vX.Y.Z`.

## 0.30.0

- Агент видит экран устройства и управляет им. Новые инструменты устройства: `screen.capture` (скриншот дисплея, уменьшенный до 1440 px, уходит модели картинкой и показывается миниатюрой в чате), `screen.windows` (приложения и окна с координатами и активное окно), `input.mouse` (переместить, клик, двойной, правый, прокрутка по координатам со скриншота), `input.type` (набрать текст), `input.key` (клавиши и сочетания вроде `cmd+shift+t`), `app.open` (приложение, файл или ссылка), `system.volume` (узнать, задать, mute). Все, кроме списка окон, идут через подтверждение.
- Реализация через штатные средства ОС без новых зависимостей: на macOS `screencapture`, `sips` и `osascript` (System Events), для перемещения мыши нужен `cliclick`; на Linux `grim`, `scrot` или `gnome-screenshot`, `xdotool`, `wmctrl`, `xdg-open`, `pactl`. Инструмент появляется у устройства, только если нужная утилита есть.
- Разрешения запрашиваются сами: после установки и после каждого обновления агент при старте просит у macOS «Запись экрана» и «Универсальный доступ» (диалоги системы для Python). Повторно: `mensarium target permissions`. Мастер `mensarium setup` предупреждает о диалогах и предлагает поставить `cliclick` через Homebrew. Статус разрешений виден в панели устройства с подсказкой, где их выдать.
- Скриншоты нужны модели с поддержкой изображений (например, qwen3-vl, gemma3, gpt-4o); модели без него ответят ошибкой провайдера. Модель видит два последних скриншота, более старые вырезаются из контекста, чтобы не тратить токены. Скриншоты хранятся артефактами задачи и удаляются вместе с чатом.
- Инструкция агента: снимать экран перед кликом, действовать маленькими шагами, проверять результат новым снимком.

## 0.29.0

- Если агент на устройстве старее Core и не поддерживает часть базовых инструментов, чат об этом говорит сам: баннер «Агент на устройстве версии X, в Core Y» с кнопкой «Обновить агента» на экране нового чата и в открытом чате (при выключенном удалённом обновлении показывается команда `mensarium update`). Агент тоже знает, что устройство устарело: в системном промпте перечислены недостающие инструменты, и на просьбу «покажи процессы» он предложит обновить агента вместо «такого инструмента нет».
- В ответе `/v1/targets` у устройства появилось поле `capabilities.missing_tools`.

## 0.28.0

- Инструменты устройства расширены с 6 до 20, все нативные в Target Agent, без шелла, с прежними проверками: пути только внутри разрешённых корней, секретные файлы и папки нельзя ни читать, ни менять, вывод редактируется.
- Чтение, без подтверждения: `files.stat` (тип, размер, права, время, число строк), `files.find` (поиск по glob вида `src/**/test_*.py`, без `.git`, `node_modules` и секретных папок), `system.info` (ОС, процессор, память, нагрузка, диск по корням, uptime, версия агента), `process.list` (процессы с фильтром), `net.ports` (слушающие порты и процессы).
- Запись, с подтверждением: `files.write` (файл целиком, атомарно, с созданием папок и сводкой изменений), `files.edit` (замена точного фрагмента, ошибка при отсутствии или неоднозначности, в ответ diff), `files.mkdir`, `files.move`, `files.copy`.
- Необратимые, всегда с подтверждением: `files.delete` (один файл или пустая папка, без рекурсии), `process.kill` (только процессы своего пользователя, не агент).
- Сеть, с подтверждением: `net.http` (GET, HEAD, POST с устройства, в том числе к localhost).
- `shell.bash`: настоящий bash-скрипт с пайпами, перенаправлениями и циклами в рабочей папке. Каждый скрипт показывается и подтверждается в режиме «С запросом действий», в режиме полного доступа выполняется сразу. Риск считается по командам скрипта (перенаправление в файл это запись, `rm` и `git push --force` необратимые), `sudo` и подобное отклоняется. На устройстве выключается флагом `allow_shell` (`mensarium target pair --no-shell`, вопрос в мастере) или переключателем в панели устройства. `shell.exec` с одной разрешённой программой остаётся для устройств без шелла.
- Профиль `coding-agent-v1` получил новые инструменты, инструкция агента переписана: правки через `files.edit` и `files.write`, команды через `shell.bash`. В чате и панели устройства есть подписи для всех инструментов.
- Старые агенты не сообщают новые инструменты, поэтому модель их не видит, пока устройство не обновится с Core.

## 0.24.0

- Навыки вынесены из плагинов в отдельный раздел «Навыки» в настройках. Навык — это папка с файлом `SKILL.md` в формате Agent Skills (agentskills.io): frontmatter с `name` и `description`, дальше инструкция в markdown. Файлы из anthropics/skills, skills.sh и ClawHub ставятся как есть.
- Два источника: встроенные навыки из поставки и свои в `~/.mensarium/core/skills/<имя>/SKILL.md`. Свой навык с тем же именем заменяет встроенный; после удаления копии встроенный возвращается. Файлы перечитываются на каждом шаге задачи, перезапуск не нужен. Папка навыков попадает в бэкап.
- На странице «Навыки»: свои и встроенные списком, переключатель у каждого, редактор с именем, описанием, инструкцией и блоком «Когда предлагать навык» (нужные инструменты, устройства по ОС, «предлагать всегда»). Встроенный навык можно открыть и сохранить как свою копию.
- Агент видит навыки компактным блоком `<available_skills>` с именем и описанием в системном промпте (бюджет 6000 символов, при переполнении описания укорачиваются), полный текст загружает через `skills.read` по имени. У `skills.read` появился `path`: чтение файлов из папки навыка (`references/*.md`), выход за папку заблокирован.
- Навык предлагается, только если он включён, ОС устройства совпадает с `metadata.mensarium.os` и все инструменты из `requires.tools` доступны на устройстве (можно шаблоны вида `mcp.github.*`); `always: true` обходит проверку инструментов. Блок `metadata.openclaw` с `os` и `emoji` тоже понимается.
- CLI на сервере Core: `mensarium skills list|show|install DIR|SKILL.md|enable|disable|remove`. REST: `/v1/skills`.
- Из манифеста плагина убрано поле `instructions`; плагин — это инструменты устройства, инструменты Core или MCP-сервер. Установленные раньше плагины-навыки при старте Core переносятся в папку навыков автоматически, у смешанных плагинов текст отбрасывается. Со страницы «Плагины» убран фильтр «Навыки».

Каталог встроен в релиз и обновляется с `https://mensarium.com/dist/plugins.json`; свой плагин добавляется манифестом в YAML.

- MCP-серверы (stdio и streamable HTTP) работают в Core или на выбранном устройстве, агент получает их инструменты как `mcp.<сервер>.<инструмент>`, аргументы проверяются по схеме инструмента.
- MCP на устройстве. Core шлёт подписанный `target.plugins`, устройство запускает сервер, только если его программа есть в списке разрешённых и включено `allow_remote_plugins`, отвечает подписанным списком инструментов, вызовы идут подписанным `mcp.call`. Серверы с секретами работают только в Core.
- В каталоге: GitHub (официальный MCP-сервер GitHub по токену), Context7 (документация библиотек), файловая система, время и часовые пояса, браузер Playwright.
- У каждого плагина с инструментами есть уровень риска: «чтение» выполняется без подтверждения, остальное — с подтверждением в режиме «С запросом действий». Подтверждение теперь работает и для инструментов, которые выполняет сам Core. Отдельные инструменты MCP можно скрыть от агента.
- Страница «Плагины»: фильтры (установленные, навыки, инструменты, MCP), форма настроек по схеме плагина с секретными полями, выбор, где запускать MCP, статус подключения и проверка, добавление своего MCP-сервера. В панели устройства — инструменты плагинов, которые на нём работают, включая MCP.
- CLI на сервере Core: `mensarium plugins list|info|install|update|remove|enable|disable|config|probe` и `mensarium mcp add|list|probe|tools|remove`; секреты вводятся без эха. На устройстве `mensarium target plugins` показывает запущенные на нём MCP-серверы; при сопряжении есть флаг `--no-remote-plugins`.
- Установленные ранее пакеты маркетплейса переносятся в плагины автоматически.

## 0.18.0

- Сновидения больше не падают на неаккуратном JSON от модели. Фаза REM просит строгий JSON по схеме (`response_format`), а если провайдер такой режим не поддерживает, повторяет запрос без него. Если ответ всё равно не разбирается, модель один раз чинит свой JSON и только потом прогон считается неудачным. Ответ REM может быть длиннее: до 4000 токенов.
- Ночной запуск идёт в часовом поясе владельца, а не сервера: веб-интерфейс сохраняет пояс браузера при открытии вкладки «Сновидения». Раньше «в 03:00» на сервере в UTC означало 06:00 по Москве.

## 0.11.0

Core отправляет подписанный запрос `target.update` (nonce, срок жизни, адресат), устройство проверяет его так же, как запросы на выполнение, скачивает версию со своего Core и перезапускается: сервис — через `mensarium update`, агент в foreground — сам. - Сновидения запускаются каждую ночь в выбранный час (по умолчанию 03:00 по времени сервера Core) или кнопкой. Ночь без новых чатов пропускается. Пока агент спит, видна текущая фаза; дневник показывает статистику, темы и ссылки на изменённые заметки.
