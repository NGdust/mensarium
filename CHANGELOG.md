# Changelog

Версии по схеме `MAJOR.MINOR.PATCH`. Источник версии — `src/__init__.py`, релиз помечается git-тегом `vX.Y.Z`.

## 0.43.0

- Провайдеры Claude Code и Codex CLI: Core находит локальные `claude` и `codex` на своём хосте (PATH и типичные каталоги, версия, статус входа, модель Codex из его конфига) и показывает их в Settings → Providers блоком «Найдено на хосте Core» с кнопкой «Подключить»; мастер `mensarium core` ставит их первыми в списке провайдеров. Ключ API не нужен, работает подписка. Модель получает каталог действий в промпте и отвечает одним JSON-объектом; встроенные инструменты Claude Code выключены, Codex работает в read-only песочнице в пустом каталоге. Картинки через эти провайдеры пока не идут.
- Исправлено: `mensarium plugins`, `mcp`, `skills`, `automations` на хосте Core снова работают после удаления admin-токена: Core выдаёт локальный токен `core-cli-token` и принимает его только с loopback.

## 0.42.0

- Встроенная автоматизация обновления клиента: при сопряжении каждое устройство получает включённую автоматизацию «Update client on <устройство>» раз в 2 часа. Агент вызывает новый инструмент Core `device.update`: тот сравнивает версию клиента с версией Core и, если клиент отстал, запускает удалённое обновление (устройство само разрешает или отклоняет его по `allow_remote_update`); при актуальной версии, офлайне или запрете ничего не делает, и запуск проходит без уведомления. Инструмент доступен только в запусках автоматизаций.
- Устройства, сопряжённые до этой версии, получают такую автоматизацию при первом старте Core один раз; удалённая автоматизация заново не создаётся. В списке автоматизаций встроенные помечены «встроенная».

## 0.41.0

- Установка одной командой без параметров: `curl -fsSL https://mensarium.com/install.sh | sh` ставит пакет и печатает подсказку. Флаги `--role/--server/--code/--name/--no-service` и команда `mensarium setup` удалены; `install.sh`, который отдаёт сам Core, тянет пакет с этого Core.
- `mensarium core` и `mensarium client` без подкоманды запускают мастер, если компонент не настроен, иначе показывают его состояние; `mensarium core setup` / `mensarium client setup` для повторной настройки.
- Мастер клиента после сопряжения спрашивает, запускать ли здесь исполнитель и открывать ли веб-интерфейс (порт, только localhost или другие машины с `allowed_hosts`), ставит нужные сервисы и печатает одноразовую ссылку для входа. `mensarium client pair` в терминале продолжает теми же вопросами.
- Команда сопряжения в UI и в `mensarium core pair-code` показывает установку и `mensarium client pair` двумя строками. README и README.ru переписаны под core, client и gateway.

## 0.40.0

- Core стал headless: интерфейс, вход по admin-токену (`/v1/auth/*`, `mensarium core token`) и встроенное устройство на машине Core удалены. Веб-интерфейс открывается только через gateway клиента; запросы `/v1/*` принимаются только из туннеля сопряжённого клиента. Публичными остаются `/healthz`, `/install.sh`, `/dist/*`, сопряжение и WebSocket клиентов.
- Старое встроенное устройство Core при первом старте помечается отозванным, каталог `core/local-target` удаляется. Telegram без явно выбранного устройства берёт первое сопряжённое.
- Мастер Core больше не спрашивает про папки и не выдаёт токен: в конце печатает, как поставить клиент и создать код сопряжения.

## 0.39.0

- Gateway: веб-интерфейс теперь может работать на машине клиента. Клиент держит к Core второе соединение (`session: gateway`), локальный сервер gateway раздаёт UI на `127.0.0.1:8790` и перекладывает запросы браузера в кадры `api.request` / `api.response` / `api.chunk` / `api.end` / `api.cancel`, которые Core разворачивает в своё же приложение без сети. Вход по локальному токену `mensarium client gateway token`, одноразовая ссылка `mensarium client gateway open`; чужие `Host` и `Origin` отклоняются.
- Команды `mensarium client gateway run|token|open|status`, сервисный юнит `gateway`; в конфиге клиента секции `worker.enabled` и `gateway` (`enabled`, `host`, `port`, `allowed_hosts`). `mensarium update` перезапускает и gateway.
- Core: эндпоинт `/v1/clients/ws` (старый `/v1/targets/ws` пока остаётся), хаб различает сессии worker и gateway, отзыв устройства закрывает обе. Статика UI переехала в пакет `mensarium.web`; UI на самом Core и admin-токен пока работают как раньше.
- UI: баннер «Core не в сети» с автоматическим восстановлением, метка «Это устройство» и значок gateway на странице устройств, текст входа под токен gateway.

## 0.37.0

- Автоматизации: задача, которую агент выполняет сам по расписанию — один раз, каждые N минут или по cron-выражению, на выбранном устройстве и в выбранном режиме доступа. Страница «Автоматизации» над «Новый чат» со списком, редактором расписания и журналом запусков; CLI `mensarium automations list|show|run|enable|disable|remove`.
- Планировщик проверяет расписания каждые 15 секунд, не больше трёх запусков одновременно; при ошибке — бэкофф 30s/60s/5m/15m/60m, после 10 подряд ошибок автоматизация отключается сама. Разовая автоматизация (`at`) отключается после успешного запуска или удаляется сразу, если включено «удалить после запуска».
- Запуск автоматизации получает в промпт отметку, что его никто не читает вживую: агент отвечает результатом или, если сообщить нечего, словом `NO_REPLY`, которое в журнал и уведомление не попадает. Результат (или ошибка) уходит владельцу в Telegram через уже привязанный канал, если уведомления включены.
- Запуски автоматизаций не занимают строку в списке чатов, но их транскрипт открывается из журнала как обычный чат.
- Агент может сам предложить автоматизацию из чата инструментами `automations.list`/`create`/`delete`, но заводит её только после явного согласия пользователя.

## 0.35.0

- План задачи: для многошаговой работы агент пишет список шагов инструментом `plan.update` и отмечает их по ходу. План показывается над полем ввода чата: выполненные шаги зачёркнуты, текущий со спиннером; когда всё готово, полоса сворачивается в одну строку.
- Субагенты: агент может запустить помощника инструментом `agent.spawn` (по образцу `sessions_spawn` в OpenClaw) и забрать его отчёт инструментом `agent.wait`. Субагент работает параллельно на том же устройстве с теми же инструментами, режимом доступа и моделью (или моделью из аргумента), видит только текст задания, вложенных помощников не запускает; одновременно работают не больше четырёх. Каждое его действие, которое требует подтверждения, по-прежнему ждёт решения пользователя.
- В чате справа от модели появляется чип с числом субагентов (пока их нет, он скрыт; точка мигает, пока кто-то работает). По клику открывается окно, где у каждого субагента видны статус, задание, действия с выводом и отчёт. Запросы подтверждения от субагентов показываются в основной ленте с меткой агента и приходят в Telegram.
- Пауза, остановка, смена режима и удаление чата действуют и на его субагентов; завершившийся чат останавливает незавершённых помощников; после перезапуска Core `agent.wait` поднимает помощников, ушедших в паузу. Субагенты не показываются в списке чатов и не попадают в сновидения памяти.

## 0.34.0

- Агент больше не отвечает «не могу», если для запроса у него нет инструмента (поиск в интернете, браузер, GitHub, база данных...). Он ищет плагин в каталоге инструментом `plugins.find` и предлагает его инструментом `plugins.install`; карточка подтверждения и есть предложение. После одобрения плагин ставится или включается, Core дожидается запуска его MCP-сервера, и агент в той же задаче выполняет исходный запрос новыми инструментами.
- `plugins.find` показывает по каждому плагину, установлен ли он, нужна ли настройка и работает ли он на устройстве; первыми идут плагины, которые работают без ключа. `plugins.install` ставит только плагины из каталога и всегда ждёт подтверждения, даже в режиме полного доступа.
- Если плагину нужен ключ или другие настройки, агент ставит его и просит ввести их в Settings → Plugins, а не в чат. MCP-сервер, который работает на устройстве, ставится на устройство текущего чата.

## 0.33.0

- Каналы: с агентом можно общаться из мессенджера. Первый канал — Telegram (Settings → Channels): вставьте токен бота из @BotFather, Core проверит его через `getMe` и начнёт слушать бота (long polling, вебхук не нужен). Первый аккаунт Telegram, который напишет боту, становится его владельцем; остальные бот молча игнорирует. Владельца можно отвязать, тогда привязка достанется следующему написавшему.
- Сообщение в боте создаёт задачу через обычный оркестратор на выбранном устройстве (по умолчанию машина с Core) и в выбранном режиме доступа; следующие сообщения продолжают тот же чат, `/new` начинает новый, `/stop` останавливает задачу, `/status` показывает состояние, `/whoami` — id аккаунта. Чат виден и в веб-интерфейсе.
- Пока агент работает, бот показывает «печатает» и одно редактируемое сообщение с последними действиями; итоговый ответ приходит отдельным сообщением с форматированием (жирный, код, ссылки, таблицы), длинные ответы делятся на части. Запрос подтверждения приходит с кнопками «Run once» и «Reject», решение с кнопки или из веб-интерфейса отражается в том же сообщении.
- Токен бота хранится в секретах Core и вырезается из текстов ошибок; кнопки подтверждения принимает только владелец. Адрес Bot API можно переопределить переменной `MENSARIUM_TELEGRAM_API`.
- Скриншот по просьбе: последний снимок экрана, сделанный агентом за ход, прикладывается к его ответу картинкой — в веб-чате под текстом ответа, в Telegram фотографией с ответом в подписи. Агент знает об этом из промпта и больше не отвечает, что не умеет присылать изображения, даже если модель сама картинки не видит.

## 0.32.0

- На macOS агент запускается через собственное приложение `~/Applications/Mensarium.app`: крошечная нативная обёртка (универсальная, arm64 и x86_64) запускает Python дочерним процессом, поэтому в «Конфиденциальность и безопасность» разрешения запрашивает и отображается Mensarium со своей иконкой, а не python3.12. Приложение создаётся при установке сервиса (`mensarium setup`, `mensarium service install target`) и удаляется при `mensarium uninstall`.
- Разрешения, выданные приложению, сохраняются при обновлениях Mensarium, пока не меняется сама обёртка.
- Ошибка «osascript is not allowed to send keystrokes» теперь сопровождается подсказкой про «Универсальный доступ».

## 0.31.0

- У провайдера появилось поле «Модель для изображений» (Settings → Providers, у Ollama Cloud и Ollama по умолчанию подсказывается `gemma4`). На шагах, где в контексте есть скриншот, Core сам подставляет эту модель, остальные шаги идут на выбранной в чате. Если поле пустое, картинка отправляется текущей модели.
- Если модель отвечает, что не принимает изображения, задача больше не останавливается: шаг повторяется без картинки, агент получает заметку, что скриншот виден пользователю в чате, а в чате появляется подсказка настроить модель для изображений.
- В Ollama Cloud картинки и инструменты поддерживают gemma4, kimi-k3, kimi-k2.6, glm-5.3-flash, deepseek-v4.1-flash, minimax-m3, mistral-large-3; gpt-oss картинки не принимает.

## 0.30.0

- Агент видит экран устройства и управляет им. Новые инструменты устройства: `screen.capture` (скриншот дисплея, уменьшенный до 1440 px, уходит модели картинкой и показывается миниатюрой в чате), `screen.windows` (приложения и окна с координатами и активное окно), `input.mouse` (переместить, клик, двойной, правый, прокрутка по координатам со скриншота), `input.type` (набрать текст), `input.key` (клавиши и сочетания вроде `cmd+shift+t`), `app.open` (приложение, файл или ссылка), `system.volume` (узнать, задать, mute). Все, кроме списка окон, идут через подтверждение.
- Реализация через штатные средства ОС без новых зависимостей: на macOS `screencapture`, `sips` и `osascript` (System Events), для перемещения мыши нужен `cliclick`; на Linux `grim`, `scrot` или `gnome-screenshot`, `xdotool`, `wmctrl`, `xdg-open`, `pactl`. Инструмент появляется у устройства, только если нужная утилита есть.
- Разрешения запрашиваются сами: после установки и после каждого обновления агент при старте просит у macOS «Запись экрана» и «Универсальный доступ» (диалоги системы для Python). Повторно: `mensarium target permissions`. Мастер `mensarium setup` предупреждает о диалогах и предлагает поставить `cliclick` через Homebrew. Статус разрешений виден в панели устройства с подсказкой, где их выдать.
- Скриншоты нужны модели с поддержкой изображений (например, qwen3-vl, gemma3, gpt-4o); модели без него ответят ошибкой провайдера. Модель видит два последних скриншота, более старые вырезаются из контекста, чтобы не тратить токены. Скриншоты хранятся артефактами задачи и удаляются вместе с чатом.
- Инструкция агента: снимать экран перед кликом, действовать маленькими шагами, проверять результат новым снимком.

## 0.28.0

- Инструменты устройства расширены с 6 до 20, все нативные в Target Agent, без шелла, с прежними проверками: пути только внутри разрешённых корней, секретные файлы и папки нельзя ни читать, ни менять, вывод редактируется.
- Чтение, без подтверждения: `files.stat` (тип, размер, права, время, число строк), `files.find` (поиск по glob вида `src/**/test_*.py`, без `.git`, `node_modules` и секретных папок), `system.info` (ОС, процессор, память, нагрузка, диск по корням, uptime, версия агента), `process.list` (процессы с фильтром), `net.ports` (слушающие порты и процессы).
- Запись, с подтверждением: `files.write` (файл целиком, атомарно, с созданием папок и сводкой изменений), `files.edit` (замена точного фрагмента, ошибка при отсутствии или неоднозначности, в ответ diff), `files.mkdir`, `files.move`, `files.copy`.
- Необратимые, всегда с подтверждением: `files.delete` (один файл или пустая папка, без рекурсии), `process.kill` (только процессы своего пользователя, не агент).
- Сеть, с подтверждением: `net.http` (GET, HEAD, POST с устройства, в том числе к localhost).
- `shell.bash`: настоящий bash-скрипт с пайпами, перенаправлениями и циклами в рабочей папке. Каждый скрипт показывается и подтверждается в режиме «С запросом действий», в режиме полного доступа выполняется сразу. Риск считается по командам скрипта (перенаправление в файл это запись, `rm` и `git push --force` необратимые), `sudo` и подобное отклоняется. На устройстве выключается флагом `allow_shell` (`mensarium target pair --no-shell`, вопрос в мастере) или переключателем в панели устройства. `shell.exec` с одной разрешённой программой остаётся для устройств без шелла.
- Профиль `coding-agent-v1` получил новые инструменты, инструкция агента переписана: правки через `files.edit` и `files.write`, команды через `shell.bash`. В чате и панели устройства есть подписи для всех инструментов.
- Старые агенты не сообщают новые инструменты, поэтому модель их не видит, пока устройство не обновится с Core.

- Выключенный инструмент Core не показывает модели и отклоняет политикой, даже если модель попробует его вызвать («инструмент выключен для этого устройства»). Настройка хранится в Core для каждого устройства, переключение пишется в журнал.
- Модели передаются только те инструменты, которые устройство реально поддерживает и которые для него включены; тот же список попадает в системный промпт.

## 0.7.0

- Модель выбирается прямо в поле ввода: кнопка с роботом и поиском по списку моделей провайдера, в новом и в открытом чате. Смена модели в чате действует со следующего шага агента, в ленте появляется отметка «Модель: …», запись идёт в журнал.
- Модель по умолчанию меняется в настройках кликом по модели из списка, без `mensarium setup`; Core сохраняет её в `config.yaml`.
- У модели иконка робота: в поле ввода, в настройках и в меню настроек.

## 0.6.0

- В настройках (Обзор) появился раздел «Резервная копия» с обеими командами: `mensarium core backup -o mensarium.pab` и `mensarium core restore mensarium.pab`, с пояснением, что делает восстановление.
- В архив `.pab` попадает встроенное устройство Core (`local-target`): после восстановления машина с Core остаётся тем же устройством, а не регистрируется заново.
- `mensarium core backup` в конце печатает команду восстановления для созданного файла.

## 0.5.0

- Полный доступ работает только там, где устройство его выполнит: агент версии 0.3.0 и новее и `allow_full_access` в его конфиге. Раньше Core на таких устройствах молча оставлял режим с запросом, а переключатель показывал «Полный доступ».
- Переключатель режима в новом и открытом чате показывает фактический режим выбранного устройства, а в меню объясняет, почему полный доступ недоступен: агент устарел или режим выключен на устройстве.
- Core отклоняет создание чата и смену режима на полный доступ для таких устройств с понятной ошибкой; в списке устройств — метка «полный доступ: обновите агент».

## 0.4.0

- Новый визуальный стиль админки: чёрная рамка, внутренняя панель со сливовой подсветкой, кнопки-таблетки, плоские фиолетовые кнопки без свечения, шрифт Onest (локально, с кириллицей), только тёмная тема.
- Лицо агента — живая сфера из частиц (canvas): вращается, волнуется и пульсирует, сильнее — когда агент думает; анимируются только видимые сферы, у ответов в ленте — статичный кадр; учитывается «уменьшить движение».
- Новый чат: сфера, шаблоны задач (подставляют текст), выбор устройства и режима в поле ввода.
- Убраны дубли: меню «Администратор», чип модели в поле ввода, устройство в поле ввода открытого чата, повторные статусы и версии в настройках; «Выйти» — в настройках.
- Сайдбар сворачивается; при скрытом сайдбаре в шапке есть кнопка нового чата.
- Причины отказов политики и статусы в журнале — по-русски; журнал показывает читаемые поля вместо JSON.

## 0.3.0

- Режимы доступа для каждого чата: «С запросом действий» и «Полный доступ» (всё без подтверждений, запрещены только привилегированные действия). Переключатель в поле ввода, смена режима пишется в журнал, при включении полного доступа висящий запрос одобряется сам.
- Полный доступ можно запретить на конкретном устройстве (`allow_full_access` в конфиге target, вопрос в мастере, `--no-full-access`); тогда Core продолжает спрашивать.
- Машина, на которой установлен Core, всегда доступна как устройство: встроенный агент регистрируется сам, без кода пары. Папки задаются в `local_target.roots` конфига Core и в мастере.
- В подписанный запрос на устройство добавлено поле `mode`; хеш политики совместим с устройствами прошлых версий.
- На мобильном меню закрывается тапом по фону.

## 0.2.2

- Свои сообщения показываются справа без подписи, ответы агента слева.
- Удаление чатов: из сайдбара и шапки чата, работающая задача сначала останавливается; запись в журнале действий сохраняется.
- Подтверждения остановки задачи и отзыва устройства — диалогом в стиле интерфейса.

## 0.2.1

- `mensarium update` перезапускает только сервисы, настроенные в текущей установке (`MENSARIUM_HOME`).

## 0.2.0

- Web UI в виде чата: сеансы по устройствам в сайдбаре, лента с ответами агента, карточками команд и подтверждениями, поле ввода с выбором устройства.
- Новая дизайн-система: тёмная тема с лавандовым акцентом, светлая тема, мобильная раскладка.
- Настройки отдельным экраном: обзор Core, модель, устройства с сопряжением по коду, профили, журнал действий.
- `mensarium update`: Core обновляется с mensarium.com, устройство — со своего Core; архив проверяется по sha256, сервисы перезапускаются.
- `mensarium version` показывает установленные роли и доступное обновление.
- Core отдаёт `/dist/latest.json`; UI помечает устройства со старой версией агента.

## 0.1.0

- Core: FastAPI, SQLite, цикл агента со state machine, approvals, аудит с цепочкой хешей.
- Target Agent: исходящее WebSocket-соединение, подписанные ED25519 запросы, nonce и срок жизни, allowlist программ и папок, вычистка секретов.
- LLM через OpenAI-совместимый API: Ollama Cloud, локальный Ollama, llama.cpp.
- Установка одним `install.sh` без Docker, мастер настройки, сопряжение по коду, сервисы launchd и systemd.
