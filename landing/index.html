You write a task in the browser on any of your machines, or in Telegram.

  • A new machine joins with a one-time code that expires in ten minutes.
  • Machines dial out to Core. They open no ports and never talk to each other.
  • The machine that runs Core is a device too. There is nothing else to install on it.

Nothing runs unsigned

When an action would change files, run a program or reach the network, the chat stops and asks. You see the exact command, the machine and the risk, and allow it once. The same request arrives in Telegram as two buttons.

read file changes run a program network access irreversible action Full access skips the wait for reads, changes and programs on a device that allows it. Irreversible actions and plugin installs still ask.

Start in two commands

One line installs uv, Python and the package into your home folder. No Docker, no accounts. Everything else is asked by the setup itself: port, model provider, which folders and programs the agent may use on this machine.

On every other machine the same installer and mensarium client: paste the pairing code, and the device is online in a few seconds.

What the agent works with

Chats are only the front. Behind them Core keeps projects with their own branches, scheduled runs, plugins and skills, notes it remembers, and a hashed activity log, all in one place and all yours.

Every screen on this page is the product as Core serves it, captured from a running installation with a few paired machines.

Bring your own model

Claude Code and Codex already on the Core host, Ollama, llama.cpp and LM Studio on your own hardware, or OpenAI, OpenRouter and any OpenAI-compatible endpoint with a key. Change the provider in settings; nothing else changes.

  • Claude CodeCLI on the Core host, its own login
  • CodexCLI on the Core host, its own login
  • Ollamalocal server or Ollama Cloud
  • llama.cpplocal server
  • LM Studiolocal server
  • OpenAIAPI key, kept in Core
  • OpenRouterAPI key, kept in Core
  • OpenAI-compatibleany base URL

Nothing leaves your machines

There is no hosted tier and no account. Core is the only process that holds keys, and it runs where you put it.

  • Keys and tokens live in Core and never reach a prompt, a device or a log. Integrations get a reference like secret://name, not the value.
  • The agent reads files, not secrets: .env, tokens and private keys are cut out before the model sees them.
  • Every request to a device carries a signature, a nonce and a deadline. A replayed or altered request is dropped.
  • Core checks mensarium.com for updates and talks to nobody else. Devices talk only to Core.
  • The activity log is a hash chain. Export a password-protected backup and move Core to another machine when you want.
