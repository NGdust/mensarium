# Mensarium

Переносимый agent harness. **Core** — headless-сервер: вызывает LLM, строит контекст, проверяет предложенные моделью действия политиками, ждёт подтверждения пользователя, пишет аудит и хранит всё состояние — SQLite, секреты, Telegram, автоматизации, плагины, навыки, память. Своего web UI у него нет. **Client** ставится на каждую машину, где агент работает или откуда им управляют: один ключ ED25519, одно сопряжение и два независимых процесса — `worker`, который исполняет подписанные запросы, и `gateway`, который раздаёт web UI на этой машине и перекладывает его в Core через собственную WebSocket-сессию.

Модель никогда не получает прямого доступа к shell, файлам, сети или секретам: она только предлагает `tool_call`, а Core решает, можно ли его выполнить.

## Установка

```sh
curl -fsSL https://mensarium.com/install.sh | sh
```

Установщик ставит [uv](https://docs.astral.sh/uv/) и Python 3.12, пакет в `~/.mensarium/venv` и команду `mensarium` в `~/.local/bin` — без параметров, без Docker. Вся настройка происходит через саму команду.

На машине, которая будет мозгом (сервер или ноутбук):

```sh
mensarium core
```

Без подкоманды запускает мастер настройки, если Core ещё не настроен (порт, адрес, LLM-провайдер и модель, сервис), или показывает состояние Core, если он уже настроен; `mensarium core setup` перенастраивает. В конце печатает `mensarium core pair-code` — одноразовый код (10 минут) для сопряжения клиентов.

На каждой машине, где агент должен работать или откуда им управляют:

```sh
mensarium client
```

Без подкоманды запускает мастер клиента, если он ещё не сопряжён: адрес Core, папки, allowlist программ, разрешения устройства, код сопряжения, затем два вопроса — запускать ли инструменты агента здесь (`worker`) и открывать ли здесь web UI (`gateway`: порт, только localhost или другие машины тоже). Мастер ставит сервисы и печатает одноразовую ссылку для входа; `mensarium client setup` перенастраивает. `mensarium client pair --server URL --code CODE --root DIR` сопрягает без мастера, а в терминале продолжает вопросами про worker и gateway.

Код сопряжения также доступен в web UI (Devices → Pair a device), где показаны и команда установки, и команда сопряжения.

Клиенты общаются только с Core и никогда друг с другом — топология звезда:

```
                     ┌──────────────────────────────┐
   Telegram ────────►│ core (headless)              │
   (канал Core)      │  orchestrator, LLM, policy   │
                     │  approvals, sqlite, secrets  │
                     │  cron, WSS /v1/clients, CLI  │
                     └──────┬────────────┬──────────┘
                    WSS     │            │     WSS
              ┌─────────────┘            └──────────────┐
              ▼                                         ▼
 ┌──────────────────────────┐                  ┌──────────────┐
 │ client (ноутбук)         │                  │ client       │
 │  worker: исполняет tools │                  │ (сервер 2)   │
 │  gateway: 127.0.0.1:8790 │                  │  worker      │
 │   └─ UI + туннель к core │                  └──────────────┘
 └────────────▲─────────────┘
              │ http://127.0.0.1:8790
         ┌────┴────┐
         │ браузер │
         └─────────┘
```

## Команды

| Команда | Что делает |
|---|---|
| `mensarium core` | Настроить Core (первый запуск) или показать его состояние |
| `mensarium core setup` | Перенастроить Core |
| `mensarium core serve` | Запуск Core в foreground |
| `mensarium core pair-code` | Одноразовый код пары (10 минут) |
| `mensarium core backup -o file.pab` / `restore file.pab` | Зашифрованный перенос Core на другой хост |
| `mensarium client` | Настроить этот client (первый запуск) или показать его состояние |
| `mensarium client setup` | Перенастроить: сопряжение, папки, worker, gateway |
| `mensarium client pair --server URL --code CODE --root DIR` | Сопряжение без мастера (`--no-full-access`, `--no-remote-update`, `--no-shell` — запреты на устройстве) |
| `mensarium client run` | Запуск worker в foreground |
| `mensarium client gateway run` | Запуск gateway (web UI) в foreground |
| `mensarium client gateway open` | Открыть web UI по одноразовой ссылке для входа |
| `mensarium client gateway token [--rotate]` | Токен для входа в web UI |
| `mensarium client gateway status` | Состояние gateway и соединения с Core |
| `mensarium client permissions` | Снова запросить у ОС screen recording и accessibility |
| `mensarium client plugins` | MCP-серверы, которые Core запустил на этом устройстве |
| `mensarium status` | Что установлено и запущено |
| `mensarium version` | Версия, компоненты на этой машине и доступное обновление |
| `mensarium update` | Обновиться: Core с mensarium.com, client со своего Core (`--check` только проверить) |
| `mensarium plugins ...`, `mensarium mcp ...`, `mensarium skills ...`, `mensarium automations ...` | без изменений (выполняются на хосте Core) |
| `mensarium service install\|stop\|restart\|logs core\|client\|gateway` | Управление сервисами |
| `mensarium uninstall --purge` | Удалить сервисы и данные |

## Как устроено

```
LLM proposal → schema validation → target capability check → policy evaluation
→ risk classification → approval (если нужен) → signed request → target execution
→ signed result → artifact → observation в контекст → следующий шаг
```

- LLM-провайдеры: Ollama Cloud, локальный Ollama, llama.cpp, LM Studio, OpenAI, OpenRouter или любой OpenAI-совместимый сервер — все через OpenAI-совместимый API. Добавляются, проверяются и переключаются в Настройки → Провайдеры (или в мастере `mensarium core`); активный провайдер меняется без перезапуска, ключи хранятся в секретах Core.
- Режимы доступа в каждом чате: «С запросом действий» (по умолчанию) и «Полный доступ». Машина с Core не является устройством сама по себе — если агент должен работать и на ней, туда тоже ставится client.
- Инструменты устройства, все нативные в client: без подтверждения (`files.list`, `files.read`, `files.search`, `files.stat`, `files.find`, `git.status`, `git.diff`, `system.info`, `process.list`, `net.ports`), изменения с подтверждением (`files.write`, `files.edit`, `files.mkdir`, `files.move`, `files.copy`, `net.http`), необратимые всегда с подтверждением (`files.delete`, `process.kill`), и `shell.bash` для настоящих bash-скриптов (проверяются и подтверждаются построчно, `sudo` отклоняется, отключается на устройстве флагом `--no-shell`). `shell.exec` запускает одну программу из allowlist без shell. Инструменты десктопа появляются, если на устройстве есть нужные утилиты ОС: `screen.capture` (скриншот, который модель видит как изображение; нужно задать «модель для изображений» у провайдера, например `gemma4` в Ollama Cloud, и Core переключится на неё на шагах со скриншотом), `screen.windows`, `input.mouse`, `input.type`, `input.key`, `app.open`, `system.volume`. На macOS worker работает через `~/Applications/Mensarium.app`, поэтому в Privacy & Security виден Mensarium, а не Python; разрешения на запись экрана и Accessibility запрашиваются после установки и после каждого обновления (`mensarium client permissions` спрашивает снова); для перемещений мыши нужен `brew install cliclick`.
- Web UI раздаёт gateway клиента, а не Core: `mensarium client gateway open` открывает его по одноразовой ссылке для входа, либо вход по локальному токену gateway (`mensarium client gateway token`, `--rotate` — заменить). Gateway отклоняет запросы, у которых `Host` или `Origin` не совпадают с его собственным адресом (`allowed_hosts` — если он слушает не только localhost). Пользователь один, а сопряжение равно полному доступу, поэтому любой gateway показывает всё состояние Core — все чаты, устройства, ожидающие подтверждения, настройки; отозвать устройство и отключить его можно на странице Devices. Если Core недоступен, UI показывает баннер «Core is offline» и сам восстанавливается, когда Core снова в сети.
- Память (Настройки → Память): заметки со ссылками `[[Название]]`, интерактивный граф связей и сновидения — ночная консолидация новых чатов в долговременную память с дневником. Агент ищет, читает и дополняет память инструментами `memory.*`, закреплённые и важные заметки попадают в системный промпт.
- Навыки (Настройки → Навыки, или `mensarium skills` на хосте Core) — это файлы `SKILL.md` в формате [Agent Skills](https://agentskills.io): frontmatter с `name` и `description` и markdown-инструкция для одного вида работы. Встроенные навыки идут вместе с релизом; свои живут в `~/.mensarium/core/skills/<name>/SKILL.md` и заменяют встроенный навык с тем же именем. В системном промпте только имена и описания в блоке `available_skills`; агент загружает навык через `skills.read`, когда задача подходит (и читает файлы навыка через `path`). Необязательный блок `metadata.mensarium` гейтит навык: `os`, `requires.tools` (глобы вида `mcp.github.*`), `always`.
- Плагины (Настройки → Плагины или `mensarium plugins` / `mensarium mcp` на хосте Core) расширяют агента: инструменты устройства — шаблоны команд, которые уходят на client как `shell.exec`; инструменты Core работают в самом Core (`web.search` через Brave Search, `web.fetch` с блокировкой внутренних адресов); MCP-серверы работают в Core или на выбранном устройстве и дают агенту `mcp.<сервер>.<инструмент>`. У плагинов есть `category`, по которой их группирует страница Plugins, настройки с секретными полями, которые остаются в Core, уровень риска, от которого зависит подтверждение, и каталог, встроенный в релиз и обновляемый с mensarium.com. Client запускает MCP-сервер, только если его программа есть в списке разрешённых устройства и оно разрешает плагины от Core. Каталог покрывает хостинг кода, документацию и веб-поиск, браузеры, базы данных, облачные и observability-сервисы, продуктивность и чаты; серверы, которым нужны ваши файлы, браузер, docker или CLI-логины, работают на устройстве. Если для запроса у агента нет инструмента (поиск в интернете, браузер, GitHub...), он ищет плагин в каталоге через `plugins.find` и предлагает его через `plugins.install`: установка всегда ждёт подтверждения, даже в полном доступе, ключи вводятся только в Настройки → Плагины, а сервер, который работает на устройстве, ставится на устройство этого чата.
- Каналы (Настройки → Каналы): общение с агентом из мессенджера. Telegram: вставьте токен бота из @BotFather; первый аккаунт Telegram, который напишет боту, становится его владельцем и единственным, кого бот слушает. Сообщения становятся задачами на устройстве, выбранном в Настройки → Каналы, иначе на первом сопряжённом устройстве, и продолжают один чат; `/new` начинает новый, `/stop` останавливает задачу. Подтверждения приходят кнопками, ответ — сообщением; токен хранится в секретах Core.
- Автоматизации (страница «Автоматизации» над «Новый чат», или `mensarium automations` на хосте Core): задача, которую агент выполняет сам по расписанию — один раз, каждые N минут или по cron — на выбранном устройстве и в выбранном режиме доступа. Запуски видны в журнале с результатом или ошибкой; повторяющиеся ошибки увеличивают паузу между попытками и в итоге отключают автоматизацию, результат можно получать в Telegram. Агент может сам предложить и завести автоматизацию, но только после вашего явного «да» в чате.
- Web UI доступен на английском (по умолчанию) и русском, переключается в Настройки → Обзор.
- Worker проверяет подпись, nonce, срок жизни запроса, хеш политики и наличие approval; пути ограничены выбранными папками, программы — allowlist-ом; `.env`, ключи и токены не читаются и вычищаются из вывода.
- Хранилище Core — SQLite в `~/.mensarium/core`; секреты — файлы с правами 0600, в UI, промпты и на клиенты не попадают.
- После рестарта Core незавершённые задачи переходят в `PAUSED` и сами не продолжаются.

## Разработка

```sh
make dev     # .venv с пакетом в editable-режиме
make lint    # ruff + mypy
make dist    # dist/: install.sh, архив и latest.json для раздачи (нужен чистый git)
make release # dist + тег vX.Y.Z
make core    # Core в foreground (нужен ~/.mensarium/core/config.yaml, см. mensarium core)
```
